1. Общая цель системы

Агент управляет логикой игры, в которой игрок развивает инди-студию через циклы разработки игры.

Главная цель игрока:

Разработать игру

Выпустить её

Получить награды (включая Game of the Year)

Повторять цикл с ростом эффективности

2. Основной цикл (Core Loop)

Агент должен поддерживать следующий цикл:

WORK (Sprint)
→ Milestone Completion
→ Milestone Result Overlay (экономика)
→ SHOP PHASE
→ следующий Sprint

Каждый Sprint = один Milestone.

3. Структура проекта

Проект имеет 3 стадии:

Prototype

Production

Polish

После завершения Polish происходит Release.

4. Логика стадий
Prototype

Малое количество задач

Низкая сложность

Минимальные требования к команде

Цель: обучающий этап

Production

Среднее количество задач

Растущая сложность

Требуется расширение команды

Экономическое давление увеличивается

Polish

Большое количество задач

Нагрузка масштабируется от общей суммы скиллов команды

Самый сложный этап

После завершения → Release

5. Milestone система

Каждый Milestone содержит:

Набор задач

DaysLimit

MoneyReward

При завершении:

Revenue = MoneyReward
SalaryCost = сумма зарплат сотрудников
NetProfit = Revenue - SalaryCost

Агент должен:

Обновить баланс

Сохранить результат

Показать MilestoneResult overlay

6. Экономика
Зарплата сотрудников

Для каждого сотрудника:

Salary = BaseSalary + (SumOfSkills * SkillFactor)

Суммарная зарплата вычитается после каждого Milestone.

Цель системы:

Сильная команда = быстрее выполняет задачи

Но увеличивает расходы

Игрок балансирует скорость и прибыль

7. Сотрудники

Каждый сотрудник имеет:

Набор скиллов

Текущее состояние (Work / Interacting / Wait)

Не может брать задачу без соответствующего скилла

Главный герой:

Не может быть уволен

Сохраняет скиллы при банкротстве

8. Shop Phase

Нанять сотрудника

Обновить доступные офферы

INSTRUCTION DOCUMENT FOR AI GAME AGENT
Project: Indie Studio Management Game
1. Общая концепция

Игра представляет собой менеджмент-симуляцию инди-студии разработки игр с мягким экономическим давлением и постепенной эскалацией сложности. Игрок проходит циклы разработки проекта, улучшает команду, управляет расходами и стремится выпустить успешную игру, получив награды.

Система должна быть расслабленной по ощущению, но требовать стратегических решений в управлении ресурсами и командой.

2. Основной игровой цикл

Игровой процесс строится вокруг повторяющейся последовательности:

Рабочий спринт (Milestone).

Завершение спринта.

Подсчёт экономики (доход, расходы, чистая прибыль).

Фаза магазина (улучшения).

Начало следующего спринта.

Каждый спринт представляет собой один Milestone проекта.

3. Структура разработки проекта

Проект делится на три стадии:

Prototype

Production

Polish

Каждая стадия состоит из определённого количества Milestone. После завершения всех Milestone стадии происходит переход к следующей стадии.

После завершения стадии Polish происходит релиз игры.

4. Логика стадий
Prototype

Это обучающая стадия.
Количество задач невелико.
Экономическое давление низкое.
Команда минимальна (обычно один сотрудник).

Цель — ввести игрока в цикл разработки и экономику.

Production

Основная стадия разработки.
Количество задач увеличивается.
Сложность растёт.
Требуется расширение команды.

Зарплаты сотрудников начинают оказывать заметное влияние на экономику.

Polish

Финальная стадия перед релизом.
Количество задач значительно увеличивается.
Нагрузка масштабируется от суммарных скиллов команды.
Это пик сложности проекта.

После завершения этой стадии происходит релиз игры.

5. Milestone

Каждый Milestone содержит:

Набор задач.

Ограничение по дням.

Денежную награду.

Milestone считается завершённым, когда все задачи выполнены.

После завершения происходит экономический расчёт:

Revenue = награда Milestone.

SalaryCost = суммарная зарплата сотрудников.

NetProfit = Revenue - SalaryCost.

Баланс игрока обновляется на величину NetProfit.

После этого отображается окно результата Milestone.

6. Экономика

Каждый сотрудник имеет зарплату.

Зарплата рассчитывается как:

BaseSalary + (SumOfSkills × SkillFactor)

Чем выше суммарные навыки сотрудника, тем дороже он обходится.

Экономическое давление создаётся балансом между:

Скоростью выполнения задач (высокие скиллы).

Расходами на зарплаты.

Денежной наградой за Milestone.

Игрок должен управлять этим балансом.

7. Сотрудники

Каждый сотрудник:

Имеет набор навыков.

Может выполнять только задачи, соответствующие его навыкам.

Потребляет зарплату после каждого Milestone.

Главный герой:

Не может быть уволен.

Сохраняет навыки при банкротстве.

Обеспечивает мета-прогресс между циклами.

8. Фаза магазина

После Milestone игрок получает возможность:

Нанять новых сотрудников.

Улучшить навыки.

Купить мебель.

Расширить офис.

Решения в этой фазе влияют на эффективность следующего спринта.

9. Релиз игры

После завершения стадии Polish происходит релиз.

Во время релиза система должна:

Рассчитать продажи.

Рассчитать долю издателя (если есть).

Рассчитать чистую прибыль.

Определить полученные награды.

Возможные награды:

Лучший арт.

Лучший геймплей.

Лучшее музыкальное сопровождение.

Game of the Year (если получены все три основные награды).

После релиза показывается окно итогов.

10. Два режима релиза
Через издателя

Есть процент издателя.

Продажи более стабильны.

Нет маркетинга.

Независимая студия

Доступна механика маркетинга.

Чем выше маркетинг — тем больше продаж.

Более высокий риск.

Более высокий потенциальный доход.

11. Победа и повторный цикл

Игрок считается успешным, если:

Выпущена игра.

Получены награды.

Если игрок терпит банкротство:

Навыки главного героя сохраняются.

Новый цикл начинается быстрее.

Игрок может оптимизировать стратегию.

Это создаёт мягкий roguelike-эффект.

12. Эскалация сложности

С ростом прогресса:

Увеличивается количество задач.

Повышается нагрузка.

Увеличиваются зарплаты.

Растёт экономическое давление.

Система должна обеспечивать ощущение постепенного усложнения без резких скачков.

13. Принципы дизайна

Игра должна:

Быть спокойной по ритму.

Давать ощущение контроля.

Не наказывать игрока чрезмерно.

Обеспечивать понятный рост сложности.

Поддерживать ощущение прогресса студии.
